# 8. Troubleshooting

[← Back to guide](../DEVELOPER_GUIDE.md)

When a build fails, read the **first** error in the output, not the last. Re-run with `--stacktrace` (or `--info`) if the message is vague. In Android Studio, the **Build** window's left-hand tree jumps straight to the failing task.

## Setup / sync problems

### "SDK location not found"
`local.properties` is missing or points to the wrong place. Open the project once in Android Studio (it writes the file), or create it yourself:
```properties
sdk.dir=C\:\\Users\\<you>\\AppData\\Local\\Android\\Sdk
```
Backslashes and `:` must be escaped exactly as shown. Alternatively, set `ANDROID_HOME` to the SDK path.

### "NDK not configured" / "No version of NDK matched the requested version 27.0.12077973"
`:metaphony` builds C++ and needs NDK **27.0.12077973**. Install it via **SDK Manager → SDK Tools → Show Package Details → NDK (Side by side)**, or run `sdkmanager "ndk;27.0.12077973"`.

### "CMake '3.22.1' was not found"
Install **CMake 3.22.1** from the same SDK Tools tab (`sdkmanager "cmake;3.22.1"`). Other CMake versions won't be picked up because the version is pinned in `metaphony/build.gradle.kts`.

### "Android Gradle plugin requires Java 17" / "Unsupported class file major version"
Gradle is running on the wrong JDK.
- Android Studio: **Settings → Build Tools → Gradle → Gradle JDK** → choose `jbr-17`/`jbr-21`.
- Terminal: point `JAVA_HOME` at a JDK 17+ (see [Environment setup](02-environment-setup.md#4-check-the-gradle-jdk)), then run `./gradlew --stop` so the old daemon goes away.

### Android Studio says the AGP version is incompatible / offers an upgrade
Your Android Studio is older than AGP 8.7.3 supports. Update Android Studio rather than downgrading the plugin. Decline the "AGP Upgrade Assistant" unless you intend to commit an upgrade.

### Gradle sync fails after pulling changes
```bash
./gradlew --stop
./gradlew :app:assembleDebug --refresh-dependencies
```
Stops stale daemons, then rebuilds while re-resolving dependencies. If Android Studio is still confused afterwards: **File → Invalidate Caches… → Invalidate and Restart**.

## Build problems

### `OutOfMemoryError` / "Daemon disappeared" / Metaspace errors
`gradle.properties` gives the Gradle daemon 2 GB (`-Xmx2048m`). R8 on release builds plus the native compile can exceed that. Raise it locally:
```properties
org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m -XX:+HeapDumpOnOutOfMemoryError -Dfile.encoding=UTF-8
```
Then `./gradlew --stop` and rebuild.

### "Unable to delete file" / "The process cannot access the file" (Windows)
A Gradle daemon, Android Studio, or antivirus has a lock on `build/`.
```bash
./gradlew --stop
```
Stops the daemons holding file handles. Then retry `./gradlew clean`. If it still fails, close Android Studio and delete `app/build` / `metaphony/build` by hand.

### Native (C++) build errors or the build hangs at `:metaphony:configureCMake…` / `buildCMake…`
Stale CMake state. `clean` doesn't remove it:
```bash
./gradlew --stop
rm -rf metaphony/.cxx metaphony/build
./gradlew :app:assembleDebug
```
Removes the native intermediates and rebuilds TagLib from scratch. Also check that `metaphony/src/main/cpp/taglib/` exists and has files. It's committed as regular files, so a normal clone includes it.

### KSP / Room errors ("Schema export directory…", "cannot find implementation for …Database")
- Room code is generated by KSP during compile. Run a full `./gradlew :app:assembleDebug` rather than relying on IDE-only builds.
- If you changed an entity and the build mentions migrations, bump the `@Database(version = …)` and add a migration (see [Project structure → Room](01-project-structure.md#room-database-schemas)).

### `assembleRelease` produced `*-release-unsigned.apk`, or "Task 'installRelease' not found"
The `SIGNING_*` environment variables aren't set in the shell that ran Gradle. See [Release & distribution](05-release-and-distribution.md#what-happens-if-the-variables-are-missing). They must be set in the **same** terminal session, and Android Studio only sees variables that existed when it was launched.

### "Keystore was tampered with, or password was incorrect" / "Cannot recover key"
The wrong `SIGNING_KEYSTORE_PASSWORD` (first message) or `SIGNING_KEY_PASSWORD` / `SIGNING_KEY_ALIAS` (second). Check against your stored credentials. In PowerShell, use single quotes for passwords containing `$` or backticks: `$env:SIGNING_KEY_PASSWORD = '...'`.

### "Keystore file '…' not found for signing config 'release'"
`SIGNING_KEYSTORE_FILE` is resolved relative to the **project root** (`rootProject.file`), not the current directory. Use `secrets/harmoniq-release.jks` or an absolute path.

## Install problems

| Error | Cause | Fix |
|-------|-------|-----|
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` / "signatures do not match" | The installed app was signed with a different key (e.g. installing your locally signed release over a GitHub release signed elsewhere, or vice versa) | `adb uninstall dev.anujyadav.harmoniq` (**deletes app data**), then install again |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | The APK's `versionCode` is lower than the installed one | Bump `versionCode`, or uninstall first |
| `INSTALL_FAILED_NO_MATCHING_ABIS` | You installed a per-ABI split that doesn't match the device (e.g. `arm64-v8a` on an x86_64 emulator) | Use `app-universal-*.apk` or the right split (`adb shell getprop ro.product.cpu.abi`) |
| `INSTALL_PARSE_FAILED_NO_CERTIFICATES` | The APK is unsigned (`*-unsigned.apk`) | Build with the signing variables set |
| `INSTALL_FAILED_OLDER_SDK` | Device runs Android < 9 (API 28) | Not supported (minSdk 28) |
| `adb: no devices/emulators found` / `unauthorized` | Device not connected / debugging not accepted | Re-plug, accept the prompt on the phone, check `adb devices`; try `adb kill-server && adb start-server` |
| "App not installed" when tapping the APK on the phone | Usually one of the signature/ABI/unsigned cases above | Install with `adb install` to see the exact error code |

Debug and release are different packages (`…harmoniq.debug` vs `…harmoniq`), so they never conflict with each other. Release and nightly *do* share an ID.

## Runtime problems

### The library is empty
Expected on a fresh install: no media folder has been chosen yet. Use the top-bar folder button or **Settings → Groove → Media folders → Add folder**. If folders are set but songs are missing, check **Settings → Groove** filters (songs filter pattern, minimum duration, blacklist/whitelist), then pull down on Home/Library to rescan.

### "Song unavailable" popup when playing
The file was deleted, moved, or folder access was revoked since the last scan. Tap **Re-scan library** in the popup to drop stale entries.

### No playback notification on Android 13+
The app requests `POST_NOTIFICATIONS` at startup. If it was denied: **Settings → Apps → Harmoniq → Notifications**, or reset with `adb shell pm clear <package>`.

### Splash screen color doesn't match the theme
The theme-matched splash only works on **Android 13+**, and it applies from the **next cold start** after a color change. Older versions show a neutral light/dark splash. To test: `adb shell am force-stop <package>`, then launch.

### Release build crashes but debug works
Almost always R8 removing or renaming something accessed by reflection or serialization. Release-type builds are minified; debug isn't.
1. Get the stack trace (`adb logcat -s HarmoniqLogger AndroidRuntime`) and deobfuscate it with `app/build/outputs/mapping/release/mapping.txt`. In Android Studio: **Build → Analyze APK** → load mapping, or use the `retrace` tool from the SDK's cmdline-tools.
2. Add a `-keep` rule to `app/proguard-rules.pro`. Existing rules already keep `kotlinx.serialization` classes and Navigation `@Serializable` routes. Global Search added DTOs (`services/globalsearch/api/Dto.kt`), WorkManager and the YouTube player without new keep rules; if a signed build fails only in Global Search, look there first.
3. To reproduce minification while debugging, temporarily uncomment the `isMinifyEnabled` / `proguardFiles` lines in the `debug` block of `app/build.gradle.kts`. **Don't commit that.**

### Global Search problems

The full table of in-app messages is in [Global Search server → Troubleshooting](09-global-search-server.md#troubleshooting-global-search). The most common ones:

| Symptom | Cause | Fix |
|---------|-------|-----|
| No **Library \| Global** switch in the Search tab | No server is known: `config/global-search.json` is empty or couldn't be read yet and the build has no built-in values, or *My own server* is selected without URL/token | **Settings → Global search → Server**: tap *Connection* to refresh, or enter your own server; for debug builds set `HARMONIQ_SERVER_URL_DEBUG` / `HARMONIQ_APP_TOKEN_DEBUG` |
| *Server unreachable* in a debug build on a phone | `adb reverse` not active (it's lost on reconnect), or the server isn't running | `adb reverse tcp:8000 tcp:8000`; `curl http://localhost:8000/readyz` on the PC |
| *Server unreachable* in a canary/release build | `http://` URL (only debug allows cleartext), or the server/tunnel is down | Use the `https://` URL; open `<url>/healthz` in the phone's browser |
| *The server didn't accept the access key…* | The token isn't in the server's `APP_TOKENS` and the config file has no newer one | Fix `app_token` in `config/global-search.json` (default server) or re-enter the token (own server) |
| Downloads fail with *Server temporarily blocked by YouTube* | Server-side: YouTube bot-checks the server's IP | Server troubleshooting: [deployment guide §15](https://github.com/AnujYadav-Dev/Harmoniq-server/blob/main/docs/deployment-guide.md#15-troubleshooting) |
| Download saved but not in the library | `Download/Harmoniq` isn't covered by a media folder | Accept the folder prompt, or **Settings → Global search → Not in library: add folder** |

`adb logcat -s HarmoniqLogger` shows the underlying error (lines starting with `GlobalSearch:`).

### The app opens a crash screen ("ErrorActivity")
That's the app's global exception handler. The stack trace is shown on screen and logged; grab it with `adb logcat -s HarmoniqLogger`.
